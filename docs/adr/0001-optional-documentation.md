# Documentation is an optional Beam capability

Decision: 2026-09-14. Supersedes the package-ownership portions of `splicewire/laravel-beam docs/adr/0211-the-openapi-artifact-is-a-core-mounted-route-behind-a-spec-source-seam.md` and the docs-seeding portions of `splicewire/laravel-beam-ux` ADR-0210.

Documentation tooling and delivery belong to `splicewire/laravel-beam-docs`. Hosts needing OpenAPI for SDK generation explicitly install it. Runtime Data declarations remain available through the lower schema foundation; removing documentation therefore does not remove route type metadata. Legacy PHP namespaces and HTTP URLs are retained under their new autoload owner.

Generic MDX compilation, entries, containment, ordinary access tokens, chrome registration and prose are UX infrastructure. Docs-specific seeds, layout, Scalar reference and Registry publishing compose them from above. The frontend capability is `@splicewire/beam-docs`.

A retained entry can require an installed capability through its separate nullable requirements column. Every requirement is mandatory and evaluated before the host's permission gate; absent handlers deny. This preserves the semantics of existing null/empty access lists and keeps capability removal effective even when a host grants all permissions to its operator. All public read surfaces share ancestry and requirement checks.

Publication is a versioned external operation over immutable generated bytes. CI and operator actions share one application service, durable attempt states and the pinned Scalar CLI. Visibility is verified against the remote destination because CLI creation flags do not establish existing Registry access policy.
